
# Menu What-If Simulator — P03

What-if симулятор меню для ресторанных сетей: baseline эконометрика (эластичность спроса,
каннибализация между похожими позициями) + слой из 15 AI-персон гостей (каждая реагирует независимо) и опциональный экспериментальный режим **MiroFish** (мультиагентная симуляция с взаимодействием агентов),
реагирующих на изменение цены, запуск комбо или удаление SKU.

## Что делает

- Загружает меню (123 SKU), историю продаж (75 дней) и комбо
- Симулирует: изменение цены ±X%, удаление SKU, запуск комбо
- Считает baseline-сценарий через эластичность спроса (own-price + cross-price/cannibalization)
- Запускает 15 виртуальных гостевых персон (запрос к Claude с ответом в JSON либо rule-based fallback без ключа)
  — показывает кто примет изменение, кто переключится на аналог, кто уйдёт
- Сравнивает выручку/маржу до/после, экспортирует markdown-отчёт со всеми допущениями
- **Агент-аналитик** (вкладка «Спроси агента»): вопрос словами -> агент сам выбирает инструмент (цена / удаление /
  комбо) -> наш код считает -> агент объясняет. Сайт показывает каждый шаг: вопрос, размышления модели, вызов
  инструмента с аргументами, результат (KPI, график куда движутся деньги, реакция персон), итоговый ответ.
  Код: `agent_trace.py` (цикл агента + трасса шагов), `agent_view.py` (визуал). Без ключа Anthropic работает
  прозрачный планировщик на правилах (помечается в ленте), расчёты те же.

## Источник данных меню

Меню и цены (123 SKU, 11 категорий) — **реальные**, выгружены с публичной страницы
[im.kz/products](https://im.kz/products) (I'M Kazakhstan, 2026-11-03). Это меню и цены,
без персональных/клиентских данных.

Что при этом НЕ публично доступно и поэтому оценено/сгенерировано:

- **Себестоимость** — на сайте нет. Взято 35% от цены (типичный food cost % для фастфуда,
  явное допущение, см. `COST_RATIO` в `data_real_im.py`). Для реального внедрения в im —
  заменить на фактическую себестоимость из их учётной системы.
- **История продаж по дням** — im.kz её не публикует. Сгенерирована синтетически (как в
  задании и разрешено: "Реальные данные — только по согласованию").
- **4 новых комбо-сценария** (`data/combos.csv`) — предложены как гипотетические новые бандлы
  из позиций, которых ещё нет в официальной категории Combo на сайте.

Если нужны реальные себестоимость/продажи — это уже отдельный запрос реальных внутренних
данных im (через KOZ AI/куратора по согласованию, как и написано в задании).

## Быстрый старт: порядок действий

Минимум (агент и сценарии, без MiroFish):

1. `cd menu_simulator && python -m venv venv && source venv/bin/activate`
2. `pip install -r requirements.txt`
3. `python data_real_im.py` -- создаёт `data/menu.csv`, `combos.csv`, `sales_history.csv` (один раз)
4. (по желанию) `export ANTHROPIC_API_KEY=...` -- агент и персоны работают на Claude и показывают его размышления;
   без ключа работают правила (в ленте агента это помечено)
5. `streamlit run app.py` -- сайт на `http://localhost:8501`

Вкладки: «Сценарий» (цена, удаление, комбо), «Спроси агента» (вопрос словами и лента шагов агента),
«MiroFish (эксперимент)», «Данные».

Дополнительно, для вкладки MiroFish (раздел ниже):

1. Запустить Docker Desktop и дождаться, пока он поднимется.
2. Первый раз: собрать и запустить контейнер по инструкции раздела MiroFish, затем `bash mirofish_patches/apply_patches.sh`
   (запускать как скрипт, не вставлять его текст в терминал). Дальше достаточно `docker start mirofish`.
3. Подождать около 20 секунд и проверить: `curl -s localhost:5001/api/graph/project/list`.
4. Запустить сайт (шаг 5 выше) и нажать «Запустить MiroFish» на его вкладке. Прогон занимает около 15 минут.

Остановка: Ctrl+C в терминале с сайтом, затем `docker stop mirofish`.

## Запуск

### Streamlit UI (основной способ)

```bash
streamlit run app.py
```

Откроется на `http://localhost:8501`. Три вкладки: Сценарий (ручная настройка), Спроси агента
(natural language), Данные (просмотр датасета).

### CLI / Python напрямую

```bash
python simulator.py
```

Прогонит 3 примера сценария (price change, removal, combo) и распечатает JSON.

```python
from simulator import simulate_price_change, simulate_removal, simulate_combo, ask_agent

result = simulate_price_change(sku_id="SKU001", price_delta_pct=0.10)   # +10% на SKU001
result = simulate_removal(sku_id="SKU006")                               # удалить SKU006
result = simulate_combo(combo_id="COMBO01")                              # запустить комбо

answer = ask_agent("что если поднять цену на Classic Beef Burger на 15%?")
```

### LLM-агент (опционально)

Без `ANTHROPIC_API_KEY` всё работает на rule-based fallback (детерминированный, без сети).
С ключом — персоны и natural-language роутинг идут через `claude-sonnet-4-5`:

```bash
export ANTHROPIC_API_KEY=sk-...
```

## MiroFish (экспериментальный режим, опционально)

[MiroFish](https://github.com/666ghj/MiroFish) — открытый движок мультиагентной симуляции: из текста-«семени»
строит граф сущностей, создаёт агентов и прогоняет их взаимодействие в симулированной соцсети (на базе OASIS),
затем ReportAgent пишет отчёт. Мы превращаем выбранный сценарий и baseline-цифры в такое «семя»
(`mirofish_adapter.build_seed`), прогоняем и показываем отчёт на вкладке «MiroFish (эксперимент)».

**Что даёт и чего не даёт.** Агенты, в отличие от наших 15 персон, общаются друг с другом, и можно увидеть,
влияет ли мнение лояльных гостей на новичков. Но результат — качественный текст, он **не меняет** выручку и
маржу (их считает только эластичность) и не доказывает поведение реальных гостей. Точность MiroFish публично не
подтверждена. Лицензия MiroFish — AGPL-3.0: при внедрении как сервиса с изменениями кода проверить обязательства.

**Запуск MiroFish** (отдельно от этого проекта; нужен Docker):

```bash
git clone https://github.com/666ghj/MiroFish && cd MiroFish
cp .env.example .env     # вписать LLM_API_KEY, LLM_BASE_URL, LLM_MODEL_NAME (формат OpenAI) и ZEP_API_KEY (app.getzep.com)
docker compose up -d     # бэкенд на :5001, интерфейс на :3000
```

Без Docker: Python 3.11-3.12 и `uv`, см. README MiroFish. В общий venv на Python 3.14 он не встаёт.

Дальше в этом проекте:

```bash
pip install -r requirements.txt
export MIROFISH_URL=http://localhost:5001      # по умолчанию уже так
python mirofish_adapter.py                      # консольный прогон (5 раундов)
streamlit run app.py                            # вкладка «MiroFish (эксперимент)»
python -m unittest tests.test_mirofish_adapter -v   # тесты адаптера на моке
```

**Стоимость и время.** Расход токенов LLM большой (авторы советуют начинать с менее 40 раундов); прогон занимает
порядка десятков минут. Стоимость зависит от выбранной модели. Отчёт MiroFish выходит на английском: бэкенд
принимает только `en`/`zh`.

**Статус проверки.** Адаптер сверен с исходниками API MiroFish и протестирован на моке (5 тестов). Полный цикл против
настоящего MiroFish (Docker, Claude Haiku 4.5 через OpenAI-совместимый endpoint) выполнен 05.11.2026 с вкладки
«MiroFish (эксперимент)»: онтология -> граф знаний -> 16 агентов -> симуляция 3 раунда (49 действий агентов:
посты, цитаты, лайки, репосты) -> отчёт ReportAgent; сценарий «+10% к цене Биф Тейсти», 905 с.

Чтобы цикл дошёл до конца, в контейнер MiroFish нужны три правки (`mirofish_patches/apply_patches.sh`):

1. рекомендательная система `twhin-bert` зависает на втором шаге симуляции -> `random` (ленту не моделируем);
2. старт симулированных суток с 11:00: агенты активны в 11-13 и 18-23, с 00:00 первые раунды пустые;
3. twitter-скрипт не писал `twitter/actions.jsonl`, из-за чего статус навсегда `running`.
   Адаптер также вызывает `close-env` после симуляции (скрипт сам не выходит) и включает запись в граф Zep.

**Что отчёт MiroFish показал и чем он НЕ является.** Качественный вывод: лояльные и нечувствительные к цене гости
принимают повышение, экономные и новые гости распадаются на жалобы, замену позиции и уход к конкурентам; доставка
называется ключевым каналом удержания. Это не количественный прогноз. 3 раунда и 49 действий -- маленькая выборка;
значительная часть текста отчёта пересказывает параметры персон, заданные нами (чувствительность к цене, лояльность),
и содержит выводы, которых в симуляции нет (названия сервисов доставки, отсутствие программы лояльности, оценки
оттока в процентах). Для решений используется только основная модель; MiroFish -- гипотезы для проверки.

**Реальные данные.** Файлы `data/raw/`, `data/real_*`, `data/*_calibration.csv` построены из выгрузки iiko клиента и
не входят в репозиторий (см. `.gitignore`). Без них проект работает на синтетических данных (`python data_real_im.py`).

## Допущения и ограничения

См. `ASSUMPTIONS` в `report.py` / раздел в каждом сгенерированном отчёте:

- Цены и ассортимент — реальные (im.kz, 2026-11-03), себестоимость — оценка 35% от цены
- Эластичность спроса задана по категориям (экспертные дефолты), не оценена регрессией по
  реальной истории цен — у im.kz нет публичной истории изменения цен
- Каннибализация: 55% потерянного спроса перетекает на substitute_group, остальное — чистая потеря
- Комбо: attach rate 20%, bundling uplift +12% — экспертные предположения
- История продаж по дням — синтетическая (im.kz её не публикует)
- **AI-персоны — качественный сигнал, не доказательство поведения реальных гостей** (явное
  ограничение из задания проекта)
